# 恐怖黎明 存档修改器（GrimDawn_SaveEditor）

用 Python 写的恐怖黎明（Grim Dawn）角色存档 `player.gdc` 图形化修改器：读取、修改、写回
全流程都带安全校验，写坏了也能提前拦住。零第三方依赖，界面用 Python 自带的 tkinter，
支持 Python 3.9+，代码与注释均为中文。

界面采用贴近游戏的暗黑风格：暗褐底、做旧古铜边框、亮金标题、羊皮纸色正文，日志页是
黑底终端观感。

当前版本 **0.1.0**。

## 快速开始

```bash
python main.py                     # 打开界面后手动选择存档
python main.py path/to/player.gdc  # 启动时直接载入某个存档
pythonw main.py                    # 不弹出黑色控制台窗口
```

运行和测试都只需要 Python 3.9+，`requirements.txt` 里没有任何运行依赖；只有打包成 exe 时
才需要 `pip install -r requirements.txt`（装 PyInstaller）。

## 项目结构

```text
main.py             程序入口（python main.py / pythonw main.py）
build.py            打包脚本：用 PyInstaller 冻结成 exe

gd_save/            核心代码
  crypto.py         存档的 GDCX 流加密与解密
  archive.py        整档解析与重建：块结构、头信息、加密状态
  items.py          嵌套结构：物品、背包、仓库、装备与快捷栏
  fields.py         可编辑字段、取值解析、阵营声望与档位
  editor.py         带安全校验的读取、校验、修改、写入，以及备份与恢复
  gui.py            tkinter 界面：工具栏、各标签页、状态栏

tests/              单元测试（合成存档，不依赖真实存档文件）
CHANGELOG.md        版本历史
```

运行只需要 `main.py` 与 `gd_save/`；测试、打包脚本和文档都不影响程序本身。

## 界面说明

窗口从上到下依次是：工具栏、存档选择下拉框、标签页、状态栏。

### 工具栏

| 按钮 | 作用 |
| --- | --- |
| 打开存档 | 选择任意 `player.gdc`，之后直接在这个文件上编辑 |
| 重新加载 | 重新读取当前文件 |
| 保存人物档 | 写回该文件（写前自动备份为 `<文件名>.<时间戳>.bak`） |
| 另存为 | 写到别处，默认文件名加 `.edited` |
| 恢复存档 | 从该文件的时间戳备份里挑一份覆盖回去；用掉的备份随后删除，其余保留 |
| 预览改动 | 只在内存里试算，改动清单进「改动日志」，不写任何文件 |
| 无损自检 | 重新编码并与原文件逐字节比对，同时检查所有块能否重写 |
| 帮助 | 关于对话框 |

工具直接在读取的那个文件上编辑：写入前会在同目录生成一份带时间戳的备份
（如 `player.gdc.20261016-164100.bak`），每次保存都是新备份、不覆盖旧的（同一秒内重复
保存会加 `-1`、`-2` 序号）。备份越多越占空间，不需要的自行删除。

点「恢复存档」会列出**这个文件**旁边的全部备份（最新的在最上面），选一份即可覆盖回那时的
状态：用掉的那份备份随后被删除，其他备份一律保留；恢复前的当前内容也会先另存为一份新的
`.bak`，所以恢复本身同样可以反悔。备份不是完整存档时（被截断、被别的东西覆盖）会拒绝恢复，
目标文件保持原样。

### 存档选择下拉框

自动扫描 `文档\My Games\Grim Dawn\save\main`（找不到时尝试 Steam 的 `userdata`）下所有
角色的 `player.gdc`，按角色子目录名列出来，选中即载入。

### 人物数据

- **人物数据**：名称、性别（游戏创建时定死，只能改存档）、专家模式、死亡次数、
  最高主线难度（普通／精英／终极）、最高炼狱难度（修习者／挑战者／角斗士）、经验、等级、
  铁币。改等级会同时写入存档头部与存档内两处。
- **属性**：力量／敏捷／智力各带「－」「＋」，每次 ±8 并联动属性点（+8 花 1 个属性点、
  -8 退 1 个，点数不足时「＋」不生效）；属性最低 50，减到 50 后「－」不再生效。
  也可以直接输入，直接输入不受联动限制；生命、能量直接输入。
- **点数**：属性点、技能点、虔诚点、累计虔诚点、贡品、回收技能点、回收虔诚点。
- **成就**：游戏成就面板的全部计数器，三列排布（击杀、伤害、竞技场、命中／暴击、
  制作、游戏时长等）。其中：
  - 「击杀复仇」是普通／精英／终极三个难度各自的复仇级（Nemesis）击杀数，
    存档里就是三个独立计数器，没有总和字段，不要合并；
  - 游戏时长接受 `80:00:00`、`80h`、`1h30m`、`90m`、`288000s` 等写法；
  - 「击杀飞升精英」只有阿斯特卡恩之牙（block16 v12）存档才有，老存档上会置灰并显示
    「此存档没有该字段」，不会被写入。

### 阵营势力

存档里的 block13（各阵营声望与解锁状态），每个阵营一行：状态下拉 + 数值框 + 解锁勾选。

- **状态**只是快捷方式：选中某档即把该档门槛值填进数值框，**真正写入存档的是数值框**，
  所以两个控件不会各写各的；数值框也接受直接填数字（如 `-500`）或档位名。
- **解锁**会同时写 `unlocked` 与 `changed` 两个字节 —— 真实存档里两者始终一致，
  只写一个会留下游戏没见过的组合。
- 存档里没有的阵营整行置灰并显示「此存档没有该阵营」，不会被写入；预留槽位（下标 29-46）
  与游戏从不显示的隐藏槽位既不展示也不修改。

### 改动日志

预览与写入的完整记录：打开的文件、界面请求的改动、实际生效的改动清单、影响字节数、
备份路径、写入后的校验结果，以及保存失败时的排查建议。预览和写入完成后会自动切到这一页。

### 状态栏

左侧是安全状态（绿色「自检通过：可以安全修改」／红色只读提示），右侧是当前操作的简要结果。

## 安全模型

改存档最怕「写坏了才发现」，所以写入被四道关卡拦着：

1. **写入前 · 无损往返自检**：`check_roundtrip()` 先「不改任何字段，解密后再加密」，
   要求与原文件逐字节一致；做不到说明文件里有本工具不认识的版本，拒绝修改。
2. **写入前 · 可重写检查**：`check_editable()` 要求所有块都能完整重新编码。存档的加密
   状态是连续演进的，只要有一个块无法解析、只能照抄，前面任何改动都会让它解出来变成
   垃圾数据，因此这类存档一律拒绝编辑。
3. **写入时**：所有可能失败的取值校验先在内存做完；新字节先写入同目录临时文件，再整档
   读回解析一遍，确认可解析后才替换目标文件。中途失败不留半成品，也不动原文件。
   目标文件已存在时备份为 `<文件名>.<时间戳>.bak`，备份失败只告警、不影响保存。
4. **写入后 · 逐字段比对**：产物立刻重新解析，与改动前的语义视图比对，凡是不在改动
   清单里的差异都会列出来并弹窗警告不要使用该文件。

图形界面永远走这套流程，没有强制开关：自检不通过时只读，「保存人物档」和「另存为」
都会拒绝写入。

## 打包成 exe（Windows）

只有这一步需要联网装包：

```bash
pip install -r requirements.txt

python build.py                  # dist/GrimDawnSaveEditor/ 整个文件夹，启动快
python build.py --onefile        # 单个 exe，方便分发，启动慢几秒
python build.py --out D:\tools   # 换输出目录
python build.py --console        # 保留控制台窗口，便于看报错
python build.py --icon app.ico   # 指定 exe 图标
python build.py --no-install     # 不自动安装 PyInstaller
python build.py --keep-build     # 保留 build/ 中间产物，便于排查
```

- `dist/GrimDawnSaveEditor/` 要**整个文件夹**一起分发（只拿 exe 会缺依赖）；
  `--onefile` 则直接发那一个 exe；
- 目标机器都不需要装 Python；`build/`（中间文件）与 `dist/`（成品）只是本地产物，可直接删除；
- 打包脚本只用标准库，缺 PyInstaller 时会自动安装。

**打包后保存存档报「没有权限」？** 通常是 exe 所在目录给它盖了 Windows 的「低完整性」标签
（`icacls <exe> | Select-String Mandatory` 出现 `Low Mandatory Level` 即是），低完整性进程
写不了「文档」这类中完整性目录，而用 `python main.py` 跑同一份代码却正常。把产物复制到
普通目录（桌面等）再运行即可，也可以用 `python build.py --out %USERPROFILE%\Desktop\grimdawn-tool`
从源头避开；打包结束时 `build.py` 会自动检测并提示。

## 注意事项

- 改档前**完全退出游戏**，否则 Windows 可能拒绝写入（失败时日志里会给出排查建议）；
- 开了 Steam 云同步的话，云端可能在之后覆盖你的改动；
- 数值改得太离谱可能出现显示异常或被游戏钳制，请留意备份；
- 本工具只用于自己的存档，请勿用于联机作弊。
